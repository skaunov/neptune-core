# Neptune Core Discovery System Adaptation

This document describes the adaptation of Polkadot SDK's discovery.rs for Neptune Core's networking architecture.

## Overview

The discovery system has been adapted from Polkadot SDK to provide peer discovery capabilities for Neptune Core using libp2p. The adaptation maintains the core functionality while integrating with Neptune's existing channel-based peer management system.

## Key Components

### 1. Core Discovery Module (`src/discovery.rs`)

**Main Features:**
- **DiscoveryConfig**: Configuration for discovery behavior adapted for Neptune's Network enum
- **DiscoveryBehaviour**: Main discovery behavior implementing libp2p's NetworkBehaviour trait
- **DiscoveryOut**: Events generated by the discovery system

**Key Adaptations:**
- Protocol naming based on Neptune's network ID system (`/neptune/{network_id}/kad`)
- Integration with Neptune's Network enum (Main, TestNet, RegTest, etc.)
- Removed Substrate-specific dependencies and types
- Adapted for Neptune's peer management architecture

**Discovery Mechanisms:**
- **Bootstrap nodes**: Hard-coded peer addresses that never expire
- **mDNS**: Local network discovery (disabled for RegTest)
- **Kademlia DHT**: Distributed hash table for peer discovery and data storage

### 2. Integration Layer (`src/discovery_integration.rs`)

**Purpose:** Bridge between libp2p discovery and Neptune's existing peer management

**Key Components:**
- **DiscoveryManager**: Manages the libp2p swarm and handles discovery events
- **DiscoveryEvent**: Events sent to Neptune's main loop
- **DiscoveryCommand**: Commands sent from main loop to discovery system
- **Address conversion utilities**: Convert between SocketAddr and Multiaddr

**Integration Features:**
- Channel-based communication with Neptune's main loop
- Automatic conversion between libp2p and Neptune address formats
- Background task management for discovery operations
- DHT value storage and retrieval for network-wide data sharing

### 3. Example Integration (`src/discovery_example.rs`)

**Purpose:** Demonstrates how to integrate discovery with Neptune's main loop

**Features:**
- Example of running discovery alongside traditional Neptune peer management
- DHT usage for network configuration and bootstrap peer updates
- Statistics and monitoring capabilities
- Event handling patterns

## Architecture Integration

### Current Neptune Architecture
```
Main Loop ←→ Peer Tasks ←→ TCP Connections
     ↓
Channel-based communication
```

### With Discovery Integration
```
Main Loop ←→ Discovery Manager ←→ libp2p Swarm
     ↓              ↓                    ↓
Channel-based   Discovery Events    Kademlia/mDNS
communication        ↓                    ↓
     ↓         Peer Discovery      Network-wide DHT
Peer Tasks ←→ TCP Connections
```

## Configuration

### Network-Specific Behavior

- **Main Network**: Full discovery enabled with mDNS and Kademlia
- **TestNet**: Full discovery with difficulty resets
- **RegTest**: Discovery disabled, mDNS disabled for controlled testing

### Protocol Naming

The Kademlia protocol name follows the pattern: `/neptune/{network_id}/kad`

Examples:
- Main network: `/neptune/0/kad`
- TestNet 42: `/neptune/45/kad`
- RegTest: `/neptune/2/kad`

## Usage Example

```rust
use neptune_core::discovery_integration::{DiscoveryManager, DiscoveryEvent, DiscoveryCommand};
use neptune_core::config_models::network::Network;

// Create discovery manager
let (discovery_tx, discovery_rx) = mpsc::unbounded_channel();
let (event_tx, event_rx) = broadcast::channel(1000);

let mut discovery_manager = DiscoveryManager::new(
    Network::Main,
    bootstrap_peers,
    event_tx,
    discovery_rx,
)?;

// Run discovery in background
tokio::spawn(async move {
    discovery_manager.run().await;
});

// Handle discovery events
while let Ok(event) = event_rx.recv().await {
    match event {
        DiscoveryEvent::PeerDiscovered { peer_id, addresses } => {
            // Handle discovered peer
        }
        DiscoveryEvent::ValueRetrieved { key, value } => {
            // Handle DHT value
        }
        // ... other events
    }
}
```
